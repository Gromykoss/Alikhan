## Баги

### 🔴 КРИТИЧЕСКИЕ

#### B1. Слепые фото: base64 всегда пустой
**Строки:** 906-989 (фото-вставка), bridge_wrapper.py:200-216  
**Симптом:** В сгенерированном ЕЖО фотографии отсутствуют.  
**Причина:** `fill_ejo.py:974` шлёт `{"message": {"key": {"id": msg_id}}}` (Evolution API формат). `bridge_wrapper.py:204` ожидает `payload["message"]["message"]["_media"]["mediaUrls"]` (Bridge формат). Объект `_media` не находится → `media_urls = []` → `local_path = None` → base64 всегда пустой.  
**Исправление:** Сменить payload на Bridge-формат, либо добавить отдельную ветку в bridge_wrapper для Evolution-формата `msg.key.id` → поиск в `bot_memory_messages` по ID → чтение `local_path` из tags.  
**Строгость:** КРИТИЧЕСКАЯ — фотоотчёт — одна из ключевых функций ЕЖО.

#### B2. Guard блокирует перегенерацию
**Строки:** 1276-1280  
**Симптом:** Нельзя перегенерировать ЕЖО — скрипт завершается, если файл уже существует.  
**Причина:** `glob.glob` проверяет наличие файла и делает `sys.exit(0)` без возможности перезаписи.  
**Исправление:** Добавить флаг `--force` / `--overwrite`, либо `os.unlink(existing[0])` перед `fill()` при явном запросе. Либо убрать guard — `fill()` и так перезаписывает файл.  
**Строгость:** КРИТИЧЕСКАЯ — блокирует весь workflow исправления ошибок в ЕЖО.

### 🟠 ВЫСОКИЕ

#### B3. Два механизма скрытия строк — один мёртвый
**Строки:** 81-202 (`_hide_rows()`), 996-1023 (inline hiding)  
**Симптом:** Строки скрываются по упрощённой логике без учёта фаз и графика из БД.  
**Причина:** Функция `_hide_rows()` (81-202) с продвинутой логикой (фазы, subsection-группировка, `bot_schedule_phases`) определена, но **никогда не вызывается** в `fill()`. Вместо неё работает inline-версия (996-1023), которая: не учитывает `bot_schedule_phases`, не группирует по subsection, не различает phase_done/phase_active.  
**Исправление:** Удалить мёртвый код `_hide_rows()`, либо заменить inline-версию на вызов `_hide_rows(ws)`. Строка 997: заменить `for r in range(24, 852): ...` на `_hide_rows(ws)`.  
**Строгость:** ВЫСОКАЯ — скрытие строк определяет читаемость отчёта. Упрощённая версия может скрыть активные строки с остатком.

#### B4. weather() — нет fallback при отказе API
**Строки:** 331-363, 654-669  
**Симптом:** При недоступности Open-Meteo ячейки погоды (G4-G8) остаются пустыми.  
**Причина:** `except: return {}` (строка 363) возвращает пустой словарь. `swaps` (666-681) использует `w.get('t')`, `w.get('w')` и т.д. — все становятся `None`.  
**Исправление:** Добавить fallback-значения: температура из кеша OJR (если есть), ветер/влажность — "нет данных". Либо `w.get('t', '—')` в swaps.  
**Строгость:** ВЫСОКАЯ — погода обязательна в ЕЖО.

#### B5. calc_completion_pct() — жёстко 6% ПСД
**Строки:** 40-78, строка 48 `PSED_WEIGHT = 0.06`  
**Симптом:** Процент завершения проекта неверен, если доля ПСД ≠ 6%.  
**Причина:** Вес ПСД захардкожен как 6% от проекта. При изменении сметы/объёмов — формула врёт.  
**Исправление:** Вычислять вес ПСД динамически: `sum(K row 1.x) / sum(K all rows)`. Либо хранить в `bot_schedule_phases` / шаблоне.  
**Строгость:** ВЫСОКАЯ — ключевой KPI проекта.

### 🟡 СРЕДНИЕ

#### B6. get_aibikon_headcount() — жёсткий fallback 5
**Строки:** 205-301, строка 218, 245, 301  
**Симптом:** При отсутствии табеля всегда показывает 5 человек АйБиКон.  
**Причина:** Три `return` с `{'total': 5, 'is_fallback': True}` — если документ не найден, не тот формат, или ошибка парсинга.  
**Исправление:** Хранить последнее известное значение АйБиКон в `ojr_section1_personnel`. При отсутствии табеля — брать оттуда.  
**Строгость:** СРЕДНЯЯ — 5 вместо реального 0 или 3 искажает статистику.

#### B7. Техника: 'бетон' матчит лишнее
**Строка:** 1086  
**Симптом:** `Бетононасос` может показать завышенное количество.  
**Причина:** `en.lower()[:5]` для 'Бетононасос' = 'бетон'. Это совпадает с 'бетономешалка', 'бетонные работы' и т.д.  
**Исправление:** Использовать полное совпадение: `len(et.split('бетононасос'))-1` или regex `\bбетононасос\b`.  
**Строгость:** СРЕДНЯЯ — только визуальное, не влияет на расчёты.

#### B8. Материалы: только известные единицы измерения
**Строки:** 1106-1121  
**Симптом:** Материалы с нестандартными единицами ('мешков', 'рулонов', 'листов', 'комплектов') не парсятся.  
**Причина:** Regex (1106) требует `м[2³]|м3|т|шт|кг|кв.м` — жёсткий список.  
**Исправление:** Добавить 'меш', 'рул', 'лист', 'компл', 'п.м' в regex. Либо сделать единицу опциональной (брать число без привязки к единице).  
**Строгость:** СРЕДНЯЯ — материалы будут пропущены в отчёте.

#### B9. yesterday_cum() — жёсткий формат имени файла
**Строка:** 583  
**Симптом:** Не находит вчерашний ЕЖО при малейшем отклонении в имени.  
**Причина:** `f"/tmp/ЕЖО_{yd.strftime('%d.%m.%y')}_АйБиКон.xlsx"` — фиксированный формат.  
**Исправление:** `glob.glob(f"/tmp/ЕЖО_{yd.strftime('%d.%m.%y')}*.xlsx")` — найти любой файл за эту дату.  
**Строгость:** СРЕДНЯЯ — при отсутствии файла используется кумулятив из шаблона (может быть устаревшим).

### 🟢 НИЗКИЕ / CODE QUALITY

#### B10. Дублирование парсинга планов
**Строки:** 522-543 и 1193-1216  
**Симптом:** Одинаковая логика `ILIKE '%план%'` + `re.findall` повторяется в `volumes()` и в секции «Материалы и планы».  
**Причина:** DRY нарушен — два независимых копирования одного алгоритма.  
**Исправление:** Вынести в `parse_plans_from_raw_messages(date)` и вызвать из обоих мест.  
**Строгость:** НИЗКАЯ — технический долг, не баг.

#### B11. staff_val('Алтын-Тас', 't') → всегда '0'
**Строка:** 659  
**Симптом:** `'Q11': staff_val('Алтын-Тас','t')` всегда возвращает '0'.  
**Причина:** `staff_val` проверяет `if contractor == 'Алтын-Тас': return '0'`. При этом в `stf` словаре Алтын-Тас может иметь реальные данные из OJR.  
**Исправление:** Убрать хардкод. Если Алтын-Тас действительно всегда 0 — захардкодить в `stf` возврате, а не в `staff_val`.  
**Строгость:** НИЗКАЯ — если Алтын-Тас действительно нет на площадке.

#### B12. timesheet: хрупкий поиск листов
**Строка:** 267  
**Симптом:** Ключевые слова 'жер', 'итр', 'айбикон', 'джеруй', 'табель' могут не покрыть новый формат табеля.  
**Причина:** Список фиксирован.  
**Исправление:** Парсить все листы, искать строку «Табель» в A1 или заголовке.  
**Строгость:** НИЗКАЯ — потребуется при смене формата табеля.
